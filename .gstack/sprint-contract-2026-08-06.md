**상태:** APPROVED

## 구현할 것
- `src/app/components/cashflow/CashflowProjectSheet.tsx` — 내부 비교 상태를 노출하지 않고 `변경 N건`만 표시한다. `N = 0`이면 버튼을 숨긴다.
- 기존 시트 stage/apply 경로 — 사용자가 `변경 N건`을 누른 뒤 명시적으로 반영할 때만 선택 월을 기존 BFF → JVM apply/readback 경로로 정합화한다.
- 공통 구성원 read model — 구성원 원장의 `nameKo + nickname`을 사용해 picker와 프로젝트 담당자 표시를 `이름(별명)`으로 통일한다.

## 성공 기준
- [ ] 단순 조회·새로고침으로 정합화 write가 발생하지 않는다.
- [ ] 화면에는 `시트↔JVM`, `시트↔저장값`, `JVM↔저장값` 중간 상태가 보이지 않는다.
- [ ] 변경이 있을 때만 `변경 N건`이 보이고, 0건이면 숨겨진다.
- [ ] 명시적 반영은 선택 월만 기존 BFF → JVM 경로로 처리한다.
- [ ] 반영 후 JVM readback으로 잔여 변경 건수를 확인하며 0건일 때만 성공 처리한다.
- [ ] 실패·409·revision 충돌·잔여 차이가 있으면 거짓 성공이나 0건을 표시하지 않는다.
- [ ] Berry가 구성원 선택 목록에 `고인효(베리)`로 표시된다.
- [ ] 저장된 담당자 문자열이 `Berry`여도 UID가 고인효 원장을 가리키면 `고인효(베리)`로 표시된다.
- [ ] 조회 중 프로젝트나 구성원 DB를 변경하지 않는다.

## 실패 기준
- [ ] 명시적 반영 없이 저장값이 변경된다.
- [ ] 선택 월 밖의 데이터나 다른 프로젝트를 덮어쓴다.
- [ ] 캐시플로우를 프론트에서 Firestore로 직접 쓴다.
- [ ] 잔여 차이가 있는데 성공 또는 0건으로 표시한다.
- [ ] Berry 중복 원장을 만들거나 프로젝트·구성원 DB를 일괄 덮어쓴다.
- [ ] 기존 결산 잠금, 승인 대기, revision, idempotency 검증을 우회한다.

- 실제 데이터 경로를 UI → BFF → JVM → persisted readback 순으로 확인한다.
- emulator는 사용하지 않는다.
- 관련 unit test와 production build를 실행한다.
- 인증된 사용자 흐름에서 조회, 변경 N건, 반영, 실패 상태를 확인한다.
- 별도 QA가 loading, disabled, error, 반복 클릭, 결산 잠금과 승인 대기를 검증한다.
