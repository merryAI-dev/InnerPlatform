# Sprint Contract: 시트 연동 경고와 월결산 결재 문서 분리
**날짜:** 2026-07-30
**예상 소요:** 2~3시간
**상태:** APPROVED

## 구현할 것
- 시트 연동에서 결산 완료 월의 변경을 주차·모드·항목·기존값·변경값 단위로 표시하고 명시적 확인 후 반영한다.
- 확인 없이 결산 완료 월 변경을 반영하는 API 우회를 차단하고 변경 이력·경고를 남긴다.
- 월결산 결재서는 요청 월의 저장 스냅샷만 프로젝트 등록 승인서와 같은 문서형 UI로 표시한다.
- 요청 당시 저장된 Spreadsheet ID·시트명·링크를 월결산 스냅샷에 고정해 조직장에게 제공한다.
- 월결산 결재는 저장 스냅샷을 사람이 검토하며 현재 시트를 다시 조회하거나 자동 재검증하지 않는다.

## 성공 기준
- [ ] 2026-07 월결산 문서에는 2026-07 Projection·Actual만 표시된다.
- [ ] 결산 완료 월의 시트 변경은 주차·항목·기존값·변경값 경고와 확인 없이 반영되지 않는다.
- [ ] 확인 후 반영하면 변경 이력과 경고가 누적된다.
- [ ] 월결산 요청 후 시트 설정이 바뀌어도 결재 문서는 요청 당시 링크와 스냅샷을 표시한다.
- [ ] 지정 조직장만 월결산 요청을 조회·승인·반려할 수 있다.
- [ ] BFF·JVM·프론트 집중 테스트와 production build가 통과한다.

## 실패 기준
- [ ] 시트 연동 경고를 결재 단계의 자동 차단으로 잘못 옮긴다.
- [ ] 결산 완료 월 변경이 확인 없이 반영된다.
- [ ] 결재 시 현재 시트를 재조회해 요청 당시 문서가 달라진다.
- [ ] 다른 월이나 연간 데이터가 월결산 문서에 섞인다.
- [ ] 기존 승인·반려·재요청·JVM 확정 흐름이 깨진다.

## 평가 방법
- 시트 연동의 stage → warning → confirm → apply 경로를 BFF/JVM 테스트로 검증한다.
- 월결산 request → pending → admin document → approve/reject를 저장 스냅샷 기준으로 검증한다.
- `/qa` 평가자 기준으로 데이터 경계·빈 링크·권한·중복 요청·오류 상태를 독립 확인한다.

## 승인된 확장: BFF↔JVM API 안정화

사용자의 2026-07-30 명시 요청으로 다음 항목을 같은 릴리스의 필수 게이트에 추가한다.

- BFF가 보내는 실제 JSON과 JVM strict DTO를 직렬화 통합 테스트로 고정한다.
- timeout·connection reset·정상 저장 후 응답 유실/드리프트를 canonical read로 조정해 `APPROVING`·`APPLYING` 고착을 복구한다.
- JVM 응답 body에 명시적 byte 상한을 두고 empty·malformed·oversized 응답을 안정적인 오류로 변환한다.
- endpoint·attempt·latency·upstream status·mutation outcome을 payload/secret 없이 구조화해 남긴다.
- 기존 tenant/auth·revision·idempotency·snapshot-only 결재·CLOSED 월 명시 확인 정책은 약화하지 않는다.

### 추가 성공 기준

- [ ] BFF close body가 실제 JVM controller에서 역직렬화되고 request-time warning evidence가 immutable close snapshot에 보존된다.
- [ ] 저장 성공 뒤 응답 유실/필드 드리프트가 발생해도 중복 반영 없이 canonical 결과로 수렴한다.
- [ ] oversized·empty·malformed JVM 응답이 프로세스 crash나 무한 불확실 상태를 만들지 않는다.
- [ ] 시트 apply와 월결산 approval의 retry/reconciliation 결과가 구분 가능한 로그와 테스트 증거로 남는다.

## 승인된 회계 기준 변경: 누적 월결산

사용자의 2026-07-30 명시 요청으로 기존의 “요청 월만 snapshot/lock” 기준을 폐기한다.

- 결산 기준 시작은 2023-01 1주차로 고정한다.
- 선택 월 결산은 2023-01부터 선택 월 5주차까지의 Projection·Actual 전체를 하나의 누적 결산 범위로 고정한다.
- 승인 완료 시 누적 범위의 모든 주차가 수정 불가 상태가 되어야 한다.
- 요청·승인 문서는 같은 누적 범위를 immutable snapshot으로 보존하고 연도·월·주차·항목별로 열람할 수 있어야 한다.
- 이후 시트 연동은 누적 마감 범위의 변경을 연·월·주차·모드·항목·기존값·변경값으로 모두 탐지하고, 명시 확인과 사유 없이 반영하지 않는다.
- 누적 snapshot은 Firestore 문서 크기 한도를 피하도록 header와 월별 shard로 저장하며, 일부 저장·부분 잠금은 성공으로 처리하지 않는다.

### 누적 결산 성공 기준

- [ ] 2026-08 결산 시 2023-01 1주차부터 2026-08 5주차까지의 모든 셀이 snapshot과 lock 범위에 포함된다.
- [ ] 중간 월 누락이나 이전 OPEN 월이 있어도 승인 결과가 부분 마감으로 남지 않는다.
- [ ] 결재 UI가 누적 범위·합계·연도/월별 상세·경고를 같은 데이터 기준으로 보여준다.
- [ ] 누적 마감 후 과거 어느 주차의 값이 달라져도 시트 연동 경고에 정확한 before→after가 표시된다.
- [ ] 900KB 단일 문서 의존 없이 재시도·idempotency·revision·감사 이력이 유지된다.

## 승인된 이력 기준: JVM 프로젝트별 회계 변경 원장

- 주정산 및 월정산에서 실제 반영된 모든 Projection/Actual 변경은 JVM이 프로젝트별 append-only 변경 원장으로 영구 보존한다.
- 각 변경 항목은 대상 월·주차·line, 이전 cell state/금액, 변경 cell state/금액, actor, 발생 시각, 사유, source revision, target revision 전후, request/approval/operation/audit 식별자를 포함한다.
- 시트에서 불러왔지만 아직 반영되지 않은 값은 candidate evidence로 구분하고, canonical 반영이 성공한 변경만 accounting change history로 기록한다.
- BFF는 JVM 원장의 조회·표시 adapter만 담당하며 별도의 canonical 변경 이력을 소유하거나 재계산하지 않는다.
- 동일 idempotency key 재시도는 이력을 중복 생성하지 않으며, canonical write와 audit history는 동일한 성공 경계에서 원자적으로 확정되어야 한다.
- 누적 월결산 승인 문서와 이후 시트 변경 경고는 JVM 원장의 관련 audit/operation 식별자를 참조할 수 있어야 한다.

### 변경 원장 성공 기준

- [ ] 주정산·월정산의 모든 실제 변경에 before/after와 행위자·사유·revision·operation 근거가 남는다.
- [ ] 재시도·응답 유실·resume에서도 같은 변경 이력이 중복 생성되지 않는다.
- [ ] canonical 반영 성공인데 이력이 없거나, 반영 실패인데 accounting history가 생성되는 부분 성공이 없다.
- [ ] 프로젝트별 이력 조회가 기간·mode·월·주차로 페이지네이션되며 BFF가 값을 재계산하지 않는다.

## 승인된 Projection 상단 지표 기준

- `현재 Projection 작성 전체 금액`은 전체 입금 합계나 BS33 잔액이 아니라 시트 Total의 `BS18 매출액(입금) + BS19 매출부가세(입금)`이다.
- 프로젝트 등록 계약금액과 위 합계의 차이 및 `합계 / 계약금액 × 100`을 표시하고, 100% 여부도 같은 값으로 판정한다.
- BS33은 잔액 검산 근거로만 유지하며 Projection 계약금액 달성률에 사용하지 않는다.

## 승인된 결산 상단 지표 기준

- 이번 주차까지의 Projection과 Actual을 같은 범위의 mode·월·주차·line별로 비교한다.
- 모든 항목 차이가 0이면 결산 지표를 `100%`로 표시한다.
- 하나라도 다르면 퍼센트 대신 항목별 차이 절댓값 합계인 `차이 N원`을 표시한다.
- 입금·출금 또는 line 차이가 상쇄되어 net만 0인 경우는 100%로 판정하지 않는다.

## 승인된 주간 준수 이력 기준

- 목요일 자정 업데이트의 주차별 판정을 JVM 프로젝트 이력으로 누적 보존한다.
- 각 이력은 연월·주차·마감기한·상태(기한 내 완료/미준수)·실제 완료시각·완료자·operation/audit ID를 포함한다.
- 대시보드 누적 건수와 `자세히` 목록은 같은 서버 이력에서 나오며 모든 과거 주차를 조회할 수 있어야 한다.
- 이후 상태 변경이나 현재 시각 재계산으로 과거 준수 판정을 덮어쓰지 않는다.

## 승인된 현금흐름 표 스크롤 UX

- Projection과 Actual 표는 각각 독립적인 가로 스크롤 영역을 갖는다.
- Projection 표 바로 아래와 Actual 표 아래 모두 scrollbar가 보여야 한다.
- 두 표의 열 너비·sticky header/first column 정렬은 유지하며 별도 JS 스크롤 동기화는 추가하지 않는다.

## 승인된 시트 공유권한 안내

- 시트 설정·연동 화면에서 공유 대상 계정 주소를 접힘/숨김 없이 즉시 표시한다.
- 해당 계정에 Google Sheet `편집자` 권한을 제공해야 한다는 설명문을 함께 표시한다.
- 계정 주소는 서버 설정 응답을 사용하며 프론트 코드에 하드코딩하지 않는다.

## 승인된 주간 정산 계약 변경

- 주간 정산 완료는 대상 주차를 포함해 앞으로 연속 15개 재무 주차(3개월)의 Projection을 작성했음을 뜻한다.
- 15주 × 16개 Projection cell에 `EMPTY`가 하나라도 있으면 서버가 완료 저장을 거절한다. 명시적 `ZERO`는 작성으로 인정한다.
- 실제 금액 변경이 없어도 사용자가 매주 `변경사항 없음`을 포함한 명시적 업데이트 완료를 저장해야 한다.
- 완료 저장 시 업데이트 결과를 `CHANGED`(변경사항 반영 완료) 또는 `NO_CHANGES`(변경사항 없음) 중 하나로 반드시 선택하고, JVM 준수 이력에 함께 보존한다.
- 관리자 화면은 프로젝트·대상 연월/주차별 완료/미완료, 완료자, 완료시각, 기한 준수 상태를 누적 이력으로 표시한다.
- JVM 이력 조회는 추적 시작 이후의 모든 대상 주차를 반환하며 상태는 `PENDING`, `MISSED`, `ON_TIME`, `COMPLETED_LATE`로 구분한다. 완료되지 않은 과거 주차도 `MISSED`로 빠짐없이 보여야 한다.
- 15주 범위는 월·연도 경계를 넘어 연속 계산하며 프론트만의 검증으로 우회할 수 없다.
