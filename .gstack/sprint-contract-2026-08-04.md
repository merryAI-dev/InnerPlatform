# Sprint Contract: 전월 월결산 회차 정렬
**날짜:** 2026-08-04
**예상 소요:** 1~2시간 + CI/배포
**상태:** APPROVED

## 구현할 것
- 서버 기준일로 월결산 회차월과 실제 결산 대상월을 구분한다.
- 기존 누적 결산 계약의 회차월은 유지하고 실제 대상월은 `throughMonth`를 기준으로 사용한다.
- 주간 현금흐름 조회월·월결산 회차월·실제 대상월의 의미를 프론트에서 혼동하지 않는다.
- JVM의 단일 대상월 마감일을 누적 결산 회차 UI에 그대로 노출하지 않는다.
- 화면에 결산 대상월과 기한을 함께 표시한다.
- AXR의 잘못 생성된 2026-08 QA 상태는 백업 후 올바른 회차로 정렬한다.

## 성공 기준
- [ ] 기준일 2026-08-04에서 주간 조회와 결산 회차는 2026-08, 실제 월결산 대상은 2026-07이다.
- [ ] 화면에 `2026-08-10까지 2026-07월 결산`이 표시된다.
- [ ] 조회·조직장 지정·요청·재요청·승인과 idempotency key는 기존 2026-08 회차를 유지하고 잠금 범위는 2026-07까지다.
- [ ] 기준일 2027-01-04에서 회차월 2027-01, 대상월 2026-12, 기한 2027-01-10으로 처리된다.
- [ ] 표적 테스트, JVM/BFF 테스트, build, 독립 QA와 live canary가 통과한다.

## 실패 기준
- [ ] 표시 문구만 바뀌고 서버의 대상월·기한 의미가 계속 어긋난다.
- [ ] 주간 조회월이 전월로 이동한다.
- [ ] 회차월을 대상월로 바꿔 누적 결산 범위가 2026-06까지로 줄어든다.
- [ ] 승인·반려·재요청 또는 중복 요청 방지 흐름이 깨진다.

## 범위 밖
- 월결산 상태 모델의 전면 재설계
- 주간 정산 주차 계산 변경
- 관련 없는 프로젝트·구성원 데이터 수정

## 평가 방법
- 기준일 고정 단위·통합 테스트로 회차월·대상월·마감일과 연도 전환 경계를 검증한다.
- 브라우저에서 AXR 프로젝트의 표시, 조직장 지정, 월결산 요청 가능 상태를 확인한다.
- 네트워크 요청·저장 문서는 회차월을 유지하면서 응답 대상월과 잠금 범위가 전월인지 확인한다.
- 인접한 loading, locked, rejected/retry, current-month rejection 상태를 회귀 점검한다.
