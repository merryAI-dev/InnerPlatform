Firebase 화이트해킹 시연 Flow

운영 Firebase 공개 API를 대상으로 한 비파괴 프로브. 실제 데이터 본문은 출력하지 않고, 차단 상태만 증거화합니다.

1. 공격 시나리오

익명 외부자

로그인 없이 Firestore 공개 API에 직접 접근합니다.

No Auth REST API

가짜 토큰

형식만 있는 Bearer token으로 인증 우회를 시도합니다.

Authorization: Bearer not-a-real-firebase-id-token

민감 경로 직접 접근

BFF 전용 연락처, 감사 로그, Storage 원본 이미지 경로를 직접 호출합니다.

contacts audit_logs business-cards

비인가 쓰기

canary 문서에 쓰기 요청을 보내 데이터 변조 가능성을 확인합니다.

orgs/mysc/whitehat_canary/whitehat-canary-deny-probe

3. 방어 지점

Firebase Auth

정상 Firebase ID token이 없으면 인증 단계에서 차단합니다.

401 Token validation

Firestore Rules

@mysc.co.kr 이메일과 org membership 문서를 기준으로 읽기/쓰기 권한을 판단합니다.

request.auth + orgs/{orgId}/members/{uid}

BFF 전용 컬렉션

contacts, business_card_imports, contact_events는 client SDK 직접 접근을 금지합니다.

allow false BFF only

Storage Rules

명함 원본 이미지는 broad allow에서 제외하고 직접 read/write를 막습니다.

orgs/{orgId}/business-cards/{allPaths=**}

발표용 결론

공개 Firebase API를 직접 두드려도 보호 경로에서 200 응답은 없었습니다. 현재 외부 비인가자는 Firestore Rules/Auth/Storage Rules에서 차단됩니다.

Firestore Rules는 외부 REST/Client SDK 접근 방어선입니다. 관리 권한, Admin SDK, GCS export 권한이 탈취되면 Rules를 우회할 수 있으므로 DB export 유출 방어는 IAM 최소권한, 서비스계정 키 금지, 감사 로그, 민감 필드 암호화가 별도 방어선입니다.
