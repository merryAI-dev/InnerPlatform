# 참여율 프로젝트 조합 및 정산 플랫폼 후보 정렬 설계

## 배경

참여인력 대시보드는 사람별 월 참여율 합계와 참여 사업 수만 보여준다. 규칙 View로 KOICA와 여러 정산 플랫폼을 묶어 보더라도 `60%`가 어떤 사업의 조합인지 화면에서 검산할 수 없다.

또한 참여율 규칙 관리의 정산 플랫폼 후보는 현재 프로젝트에서 발견된 값만 노출한다. 프로젝트 등록·수정 화면이 지원하는 표준 플랫폼 전체와 후보 범위가 달라, 아직 등록 사업이 없는 플랫폼은 규칙을 미리 만들 수 없다.

## 목표

1. 전체 보기에서는 현재처럼 사람별 월 합계만 간결하게 보여준다.
2. 사용자 정의 규칙 View에서는 사람별 합계를 유지하면서 프로젝트별 월 기여율을 펼쳐 볼 수 있게 한다.
3. 규칙 관리의 정산 플랫폼 후보를 프로젝트 등록·수정의 표준 플랫폼 목록과 일치시킨다.
4. 현재 사업이 없는 플랫폼도 `0개`로 표시하고 선택 가능하게 한다.
5. 합계와 상세가 동일한 서버 집계에서 생성되도록 하여 화면에서 항상 검산 가능하게 한다.

## 화면 동작

### 전체 보기

- 현재 사람별 합계 표를 그대로 유지한다.
- 프로젝트 상세 펼침 버튼과 상세행을 표시하지 않는다.
- `프로젝트 N개` 표시는 기존 요약 역할만 유지한다.

### 사용자 정의 규칙 View

- 각 사람 행은 기본적으로 접힌 상태다.
- 참여 사업 셀에 `AXR프로젝트경비 외 3개 · 총 4개`처럼 첫 프로젝트명과 전체 수를 표시한다.
- 참여 사업 셀의 버튼을 누르면 같은 표 안에서 프로젝트별 행이 사람 행 바로 아래 펼쳐진다.
- 프로젝트 상세행은 사람 합계와 동일한 12개월 열을 사용한다. 중첩 테이블이나 별도 가로 스크롤 영역을 만들지 않는다.
- View 또는 연도를 변경하면 펼침 상태를 초기화한다. 이전 조건의 프로젝트 상세가 새 조건 아래 잠시 남지 않게 한다.
- 전체 펼치기 기능은 이번 범위에 포함하지 않는다.

예시:

```text
김정태   ▾ AXR프로젝트경비 외 3개   60%   60%   50%
         ├ AXR프로젝트경비           20%   20%   20%
         ├ KOICA 역량강화            30%   30%   20%
         └ RCMS 사업                 10%   10%   10%
```

### 월 상태 표현

- 입력된 양수: `20%`
- 명시적으로 입력된 0: `0%`
- 투입기간 안의 빈칸 또는 `null`: `미입력`
- 투입기간 밖: `—`
- 일부 프로젝트가 미입력인 사람 합계는 현재 경고 의미를 유지한다.

## 정산 플랫폼 후보

- 프로젝트 등록·수정과 참여율 규칙 관리는 동일한 표준 코드·라벨 목록을 사용한다.
- e나라도움, IRIS, RCMS, 이지바로 등 표준 플랫폼은 현재 등록 사업 유무와 관계없이 항상 노출한다.
- 각 후보에 현재 유효 프로젝트 수를 `RCMS 0개`, `e나라도움 12개`처럼 표시한다.
- `0개` 후보도 선택하고 규칙에 저장할 수 있다. 이후 해당 플랫폼 사업이 등록되면 기존 규칙에 자동으로 포함된다.
- `기타`는 등록·수정과 동일한 하나의 표준 유형으로 표시하고, 세부 시스템명을 별도 규칙값으로 늘리지 않는다.
- 동일 차원 안의 여러 선택은 OR, 고객 조건과 정산 플랫폼 조건 사이는 AND, 비어 있는 차원은 전체 허용이라는 기존 규칙을 유지한다.
- 기존 규칙을 자동 변경하거나 새 후보를 자동 선택하지 않는다.

## 데이터 흐름

### 프로젝트별 참여율

- 기존 `GET /api/v1/participation-dashboard`가 읽는 프로젝트·참여행·사람·규칙 스냅샷을 그대로 사용한다.
- 서버가 사람별 합계를 만드는 시점에 `projectId`별 월 기여율도 함께 누적한다.
- 별도 프로젝트 상세 API, 펼침 시 추가 요청, Firestore 추가 조회는 만들지 않는다.
- 사용자 정의 규칙 View 응답의 각 사람에 선택 연도 기준 `projects`를 포함한다.
- 전체 보기 응답에는 프로젝트 상세를 포함하지 않거나 빈 배열로 내려 응답 크기를 제한한다.

응답 개념:

```ts
projects: Array<{
  projectId: string;
  projectName: string;
  months: Array<{
    yearMonth: string;
    label: string;
    rate: number;
    isConfirmed: boolean;
    hasMissing: boolean;
    isWarning: boolean;
  }>;
}>;
```

### 집계 불변식

- 사람 월 합계는 포함된 프로젝트 월 확정값의 합과 같다.
- 사람의 `hasMissing`은 포함 프로젝트 중 하나라도 미입력이면 참이다.
- `projectCount`는 전체 계약기간이 아니라 선택 연도에 소유 월이 하나라도 있는 고유 `projectId` 수다.
- 명시적 0만 있거나 전월 미입력인 프로젝트도 참여·점검 대상이므로 포함한다.
- 선택 연도에 소유 월이 전혀 없는 프로젝트는 상세와 `projectCount`에서 제외한다.
- 같은 이름의 서로 다른 프로젝트는 `projectId`로 구분한다.
- 같은 프로젝트의 여러 투입 구간은 프로젝트 상세행 하나로 합친다.
- 같은 사람·프로젝트·월에 `PROJECT_TEAM_SYNC`가 있으면 기존 정책대로 해당 월의 `MANUAL` 값을 중복 합산하지 않는다.
- 규칙 밖 프로젝트와 People 미연결 참여행은 사람 합계와 프로젝트 상세 양쪽에서 제외한다.

### 정산 플랫폼 후보 데이터

- 서버 후보 목록은 프로젝트 등록·수정의 표준 코드·라벨 계약과 동일해야 하며, 목록 일치 회귀 테스트로 두 경로의 어긋남을 막는다.
- 서버는 표준 후보 전체에 현재 프로젝트 수를 결합한다.
- 프로젝트 수는 규칙 필터와 동일한 정산 플랫폼 정규화 정책을 사용한다. 레거시 사업도 기존 변환 규칙에 따라 알맞은 플랫폼으로 집계한다.
- 기타 시스템의 프로젝트 수는 표준 `OTHER` 유형 하나에 합산한다.

## 접근성 및 반응형

- 프로젝트 펼침은 실제 `button`을 사용한다.
- 버튼에 사람 이름을 포함한 접근성 이름, `aria-expanded`, `aria-controls`를 제공한다.
- Enter와 Space로 열고 닫을 수 있고, 접은 뒤에도 포커스가 버튼에 남는다.
- 프로젝트명은 tooltip에만 숨기지 않고 실제 텍스트로 렌더링한다.
- 기존 사람·참여 사업 sticky 열과 단일 가로 스크롤 구조를 유지한다.
- 상세행도 부모 표의 월 열을 그대로 사용해 모바일에서 월 정렬이 깨지지 않게 한다.

## 오류 및 호환성

- 로딩·빈 상태·서버 오류는 기존 대시보드 상태를 유지한다.
- 구버전 응답처럼 프로젝트 상세가 없으면 펼침 버튼을 표시하지 않고 사람 합계는 정상 렌더링한다.
- View 또는 연도 요청이 교체되는 동안 이전 상세를 새 조건의 결과로 표시하지 않는다.
- 펼침과 접힘은 읽기 전용이며 DB 쓰기나 외부 연동을 발생시키지 않는다.

## 검증 계획

### 서버 단위 테스트

- 두 프로젝트의 `40% + 20% = 60%` 합계·상세 일치
- 명시적 0, 빈칸/null, 투입기간 밖 상태 구분
- 동일 사람·프로젝트·월의 시트 값이 수기 값을 대체
- 규칙 밖 프로젝트 미노출
- 선택 연도 밖 프로젝트가 `projectCount`에 포함되지 않음
- 동일 프로젝트 여러 구간은 한 상세행, 동명 다른 프로젝트는 별도 상세행
- 전월 미입력 또는 전월 명시적 0 프로젝트도 선택 연도 프로젝트로 포함

### 저장→조회 통합 테스트

- Firestore에 저장된 KOICA·정산 플랫폼 조합을 기존 참여율 HTTP 경로로 조회한다.
- 동일 차원 OR, 차원 간 AND, 빈 차원 wildcard를 유지한다.
- 사람 합계, 프로젝트 상세, `projectCount`, 선택 연도 12개월이 일치하는지 검증한다.
- 조회 전후 프로젝트·참여행 문서가 변하지 않는지 확인한다.
- 표준 정산 플랫폼 전체가 노출되고 사업 수가 0인 후보도 규칙 저장에 성공하는지 검증한다.

### 화면 검증

- 전체 보기에는 펼침 버튼이 없다.
- 규칙 View는 기본 접힘이고 사람별로 독립적으로 펼쳐진다.
- 반복해서 열고 닫아도 상세행과 네트워크 요청이 늘지 않는다.
- 키보드 조작, 접근성 속성, 긴 프로젝트명, `0%`·`미입력`·`—`를 확인한다.
- 375px 화면에서 페이지 전체가 아니라 표 컨테이너만 가로 스크롤되는지 확인한다.
- 기존 로딩·빈 상태·오류 상태를 회귀 확인한다.

## 범위 밖

- 참여율 원본 저장 방식 변경
- 새로운 프로젝트 상세 조회 API
- 전체 보기의 프로젝트 상세 펼침
- 모든 사람을 한 번에 펼치는 기능
- 플랫폼 후보를 규칙에 자동 선택하거나 기존 규칙을 자동 수정하는 기능
- 정산 플랫폼별 별도 색상 체계

## 완료 기준

1. 전체 보기는 기존 사람별 합계만 표시한다.
2. 사용자 정의 규칙 View에서 프로젝트별 월 기여율을 사람별로 펼쳐 검산할 수 있다.
3. 사람 합계와 프로젝트 상세 합계가 모든 월에서 일치한다.
4. 프로젝트 수가 선택 연도·선택 규칙의 실제 프로젝트 수와 일치한다.
5. 등록·수정과 규칙 관리가 같은 정산 플랫폼 후보를 사용한다.
6. 사업 수 0개인 플랫폼도 보이고 선택·저장할 수 있다.
7. 추가 DB 읽기·쓰기 없이 기존 대시보드 조회 한 번으로 동작한다.
8. 단위·통합·화면·접근성·빌드 검증이 모두 통과한다.
