# SPEC-09 — 시트 동기화 단일화 (Stream 5)

**작성:** 2026-08-08 · **선행:** spec-08(3-스트림 설계 + Stream 4), PR #482(템플릿 인덱스)
**사용자 확정 사항 (2026-08-08):**
1. **실무자 입력 창구는 스프레드시트가 유일하다.** 동기화 견고성에 투자한다.
2. **빈칸(미입력)과 0(0원 확정)의 구분은 명확한 의도다. 반드시 보존한다.**
3. 낙오 데이터 정리는 전 프로젝트 일괄, 스프레드시트 형식 기준. 양식이 불명확하면 **반드시 질문**.
4. **수동 반영만** (검토→적용). 자동 주기 동기화 없음.

---

## 0. 왜 — 확정된 사고 3건 (전부 라이브 실물 확인)

| 사고 | 실물 증거 | 뿌리 |
|---|---|---|
| 연 단위 관리 연도(2025)에 주차 경고 | `p1773651024850-2025-12-w4` 문서에 `SALES_IN 7,582,243` 실존. 8개 프로젝트 28건 + 2024 낙오 33건 | 과거 동기화가 연 단위 연도에 주차 문서 생성 |
| 2025 Actual 미표시 (시트 317,449,417) | 연간 집계 2025 = 7,582,243 — 시트 연간 열이 아니라 낙오 주차 값과 일치 | 집계가 시트가 아닌 파생 사본에서 재파생 |
| 리더십살롱 "Total 미입력" 치명 에러 | mirror 1,920셀 정상, 주차 문서 60건 정상(2026만). **시트 ACTUAL 잔액 행이 1칸 좌측 시프트** (TSV 실물) → 고정 열 파서가 Total 칸을 EMPTY 판정 → `control_total_missing` (`cashflow-sheet-snapshot.mjs:320`) → 반영 차단 | 위치 기반 파싱이 뒤틀린 행에 무방비 + 에러가 원인 칸을 못 짚음 |

공통 뿌리: **시트 1벌 → 파생 사본 3벌(mirror·cashflow_weeks·year_totals)**, 사본마다 다른 화면이 읽고, 사본이 어긋나면 화면이 거짓말한다.

## 1. 원칙

- 시트 = 실무자 입력의 SSOT. 파생 사본은 **반영(apply) 시점에만** 갱신되는 캐시이며, 서로 독립 갱신 금지.
- `EMPTY ≠ ZERO` 불변식: 파서→mirror→canonical→화면 전 구간에서 상태 보존. PR #482의 2비트 상태 팩킹이 이 4상태(EMPTY/ZERO/VALUE/INVALID)를 위해 설계됨.
- 주별/연간 경계는 템플릿 계약 상수 (`appliedWeeklyYears`가 이미 존재 — 이를 유일한 판정자로 승격). 연 단위 연도에 주차 문서 생성 금지.
- 수동 반영만. 자동 트리거 추가 금지.
- 에러는 설명 가능해야 한다: "무슨 행·무슨 칸이 왜"까지. `control_total_missing` 같은 코드만 던지고 끝나면 실패.

## 2. 작업 단위

### 5-A. 뒤틀린 행 방어 + 설명 가능한 진단 (치명 에러 해소 — 최우선)
- 파서가 행 길이를 템플릿 폭과 대조. 짧으면/시프트 의심이면: 헤더·라벨 열로 **행 앵커링** 후 재정렬 시도, 불가하면 정확한 위치를 지목하는 안내 생성 — 예: "ACTUAL '잔액' 행(41행)이 다른 행보다 1칸 짧습니다. 시트에서 셀 삭제로 열이 밀렸는지 확인해 주세요 (G41 부근)."
- `control_total_missing` 에러에 행 라벨·A1 좌표·기대 열 수 vs 실제 열 수 포함.
- 수용 기준: 리더십살롱 TSV를 fixture로 → ①시프트 감지 ②원인 칸 지목 ③Total 1,818,182/2,000,000 정상 파싱(재정렬 성공 시). **빈칸과 0 구분 보존 단언 필수.**

### 5-B. 연간 열 직결 (Actual 미표시 해소)
- 연간 집계(`cashflow_sheet_year_totals`)는 **시트 연간 열에서만** 쓴다. 주차 문서에서 재파생 금지.
- 연 단위 연도의 시트 열 값 ↔ 집계 문서 필드 1:1. EMPTY는 EMPTY로 저장(0으로 뭉개기 금지 — 기존 `wholeWon` 사건과 동일 원칙, PR #481 참조).
- 수용 기준: p1773651024850 fixture → 2025 집계 = 317,449,417. 상태 분포에 EMPTY 보존.

### 5-C. 주차 문서 생성 게이트
- 반영 파이프라인에서 연 단위 관리 연도의 주차 문서 생성을 차단 (#482 `weekOrdinal` 거부 로직 재사용 또는 동일 규칙).
- 수용 기준: 연 단위 연도 데이터가 포함된 fixture 반영 → 주차 문서 생성 0건, 연간 집계만 갱신.

### 5-D. 낙오 정리 스크립트 (dry-run 전용)
- 대상: 연 단위 관리 연도의 `cashflow_weeks` 전 프로젝트 (확인된 61건+, 정확 목록은 스크립트가 산출).
- 워커는 **dry-run 스크립트와 백업 export 스크립트까지만** 작성. **라이브 실행 금지** — 실행은 코디네이터가 백업 확인 후 별도 진행.
- 출력: 프로젝트별 삭제 대상 목록, 삭제 후 재동기화(수동 반영) 필요 프로젝트 목록.

### 5-E. 사본 계보 문서화
- mirror·weeks·year_totals 각각 누가 언제 쓰는지, 반영 이후 읽기 전용인지 표로. (다음 단계 사본 축소의 입력)

## 3. 금지

- 자동 동기화 추가
- EMPTY→0 변환 (어디서든)
- 연 단위 연도 주차 문서 생성
- 라이브 DB 쓰기/삭제 (스크립트는 dry-run 출력까지)
- 판정 로직(BFF/JVM 경계) 변경 — 이 스트림은 시트→저장 구간만
- 시트 양식 추정 — 불명확하면 **질문으로 중단** (사용자 지시)

## 4. 검증 규율

- 두 실사고 시트(리더십살롱·p1773651024850 상당 fixture)를 계약 테스트로 고정
- 사보타주: ①행 시프트 fixture에서 감지 로직 제거 시 테스트 실패 ②EMPTY/ZERO 구분 제거 시 실패 확인 후 원복
- 반영 전후 SPEC-04 필드 불변 (결산 이력 무접촉)
