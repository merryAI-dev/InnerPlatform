# SPEC-09 — 시트 동기화 단일화 (Stream 5)

**작성:** 2026-08-08 · **선행:** spec-08(3-스트림 설계 + Stream 4), PR #482(템플릿 인덱스)
**사용자 확정 사항 (2026-08-08):**
1. **실무자 입력 창구는 스프레드시트가 유일하다.** 동기화 견고성에 투자한다.
2. **빈칸(미입력)과 0(0원 확정)의 구분은 명확한 의도다. 반드시 보존한다.**
3. 낙오 데이터 정리는 전 프로젝트 일괄, 스프레드시트 형식 기준. 양식이 불명확하면 **반드시 질문**.
4. **수동 반영만** (검토→적용). 자동 주기 동기화 없음.

## 0. 왜 — 확정된 사고 3건 (전부 라이브 실물 확인)

| 사고 | 실물 증거 | 뿌리 |
|---|---|---|
| 연 단위 관리 연도(2025)에 주차 경고 | `p1773651024850-2025-12-w4` 문서에 `SALES_IN 7,582,243` 실존. 8개 프로젝트 28건 + 2024 낙오 33건 | 과거 동기화가 연 단위 연도에 주차 문서 생성 |
| 2025 Actual 미표시 (시트 317,449,417) | 연간 집계 2025 = 7,582,243 — 시트 연간 열이 아니라 낙오 주차 값과 일치 | 집계가 시트가 아닌 파생 사본에서 재파생 |
| 리더십살롱 "Total 미입력" 치명 에러 | mirror 1,920셀 정상, 주차 문서 60건 정상(2026만). **시트 ACTUAL 잔액 행이 1칸 좌측 시프트** (TSV 실물) → 고정 열 파서가 Total 칸을 EMPTY 판정 → `control_total_missing` (`cashflow-sheet-snapshot.mjs:320`) → 반영 차단 | 위치 기반 파싱이 뒤틀린 행에 무방비 + 에러가 원인 칸을 못 짚음 |

공통 뿌리: **시트 1벌 → 파생 사본 3벌(mirror·cashflow_weeks·year_totals)**, 사본마다 다른 화면이 읽고, 사본이 어긋나면 화면이 거짓말한다.

## 1. 원칙

- 시트 = 실무자 입력의 SSOT. 파생 사본은 **반영(apply) 시점에만** 갱신되는 캐시이며, 서로 독립 갱신 금지.
- `EMPTY ≠ ZERO` 불변식: 파서→mirror→canonical→화면 전 구간에서 상태 보존. PR #482의 2비트 상태 팩킹이 이 4상태(EMPTY/ZERO/VALUE/INVALID)를 위해 설계됨.
- 주별/연간 경계는 템플릿 계약 상수 (`appliedWeeklyYears`가 이미 존재 — 이를 유일한 판정자로 승격). 연 단위 연도에 주차 문서 생성 금지.
- 수동 반영만. 자동 트리거 추가 금지.
- 에러는 설명 가능해야 한다: "무슨 행·무슨 칸이 왜"까지. `control_total_missing` 같은 코드만 던지고 끝나면 실패.

## 1-B. 시트 양식 계약 (전사 고정 — 실물 샘플 3건으로 확정, 2026-08-08)

**열 구조 (총 71열):**

| 열 | 내용 |
|---|---|
| 1 | 라인 라벨 (예: `매출액(입금)`) |
| 2 | 입력기준 설명 (파싱 대상 아님) |
| 3~4 | 과거 연간 열 (2024년, 2025년) |
| 5~64 | **주차 그리드 60칸 — 올해만** (`26-1-1`~`26-12-5`) |
| 65~70 | 미래 연간 열 (2027~2032) |
| 71 | Total (수식 — 대조 검증용) |

**행 구조:** IN 7행(선입금×3·매출액·매출부가세·팀지원금·은행이자) + `입금 합계` + OUT 9행 + `출금 합계` + `잔액 (※ 중요)`. 합계·잔액 행은 수식 행 — **값 저장 금지, 대조 검증(control total)에만** 사용. Projection 블록과 ACTUAL 블록이 같은 구조로 반복.

**규칙:**
1. **주차 해상도는 "올해"만** (사용자 확정: "올해 아니면 주차 별도로 없음"). 주별 연도는 하드코딩(2026)이 아니라 **시트 헤더의 주차 라벨(`26-x-x`)에서 파생**한다 — mirror의 `activeWeekRange.source='sheet_header'`가 이미 이 방식이며 이를 유일 판정자로 승격.
2. **통화 표기 정규화**: 셀 값은 `₩0`, `196,000,000`, 맨숫자 모두 가능. `classifyCashflowSheetCell`(`cashflow-sheet-snapshot.mjs:28`)이 `₩￦원, 공백` 제거 처리 — 이 함수를 유일한 셀 분류기로 유지. Total 열은 무표기 숫자로 올 수 있음(수식 서식 차이).
3. **EMPTY 판정**: 빈칸·대시(`-`)만 EMPTY. `₩0`은 ZERO. (사용자 확정: 구분은 명확한 의도)
4. **행 앵커는 라벨**: 시작 행 번호는 프로젝트마다 다를 수 있다 (리더십살롱: Projection 18행, ACTUAL 41행). 절대 행 번호 의존 금지. 라벨 미일치 시 추정하지 말고 진단 메시지로 중단.
5. **연도 전환(rollover)**: 해가 바뀌면 작년 주차 열이 연간 열로 접힌다. 작년 주차 문서의 처리(연간 집계로 접기)는 **5-F 후속 단위** — 이번 배치 범위 아님. 낙오 정리(5-D)에서 작년 주차 문서 삭제 전 **시트 연간 열과 합계 대사 일치 확인**을 삭제 게이트로 추가한다.

## 2. 작업 단위

### 5-A. 양식 불일치 = 즉시 경고 (사용자 확정 방침, 2026-08-08)

**방침: 고치려 들지 말고, 다르면 다르다고 알린다.** 재정렬·복구 시도는 **하지 않는다.** 사용자 지시 원문: "시트양식이 다르면 시트 양식이 다르다고 경고를 띄워. 그거 검증으로 시간이 더 걸리면 최악이다."

- **행 폭 게이트 하나만 추가한다.** 각 데이터 행의 배열 길이를 템플릿 폭(71)과 대조. 불일치면 즉시 실패. 비용은 행당 정수 비교 1회(약 70회) — **측정 불가 수준이며 응답 시간에 영향 없다.** 무거운 탐색·추정·재배치 알고리즘 금지.
- **fail-closed 로 전환.** 현재는 `sheetFacts.issues` 가 있어도 snapshot 이 항상 `FRESH`, refresh run 이 항상 `COMPLETED` 다 (조사 B §2 확인). 양식 불일치는 **template 실패 경로**로 보내 기존 `lastRefreshError.diagnostics` 로 화면에 뜨게 한다 — 이미 Lab UI 에 노출되는 경로다(`CashflowSheetLabPage.tsx:1129-1145`). 새 UI 를 만들지 않는다.
- **메시지는 위치를 지목한다.** 예: "'잔액' 행의 칸 수가 양식과 다릅니다 (양식 71칸, 현재 70칸). 시트에서 셀이 삭제되어 값이 밀렸는지 확인해 주세요." 기술 용어·내부 코드명 금지.
- **한계를 문서에 남긴다.** 폭이 같은 값 교환(조사 B P0-3)은 이 게이트로 못 잡는다. 검출 비용이 크므로 **의도적으로 잡지 않는다** — 스펙에 명시하고 넘어간다.

**수용 기준:** ①짧은 행 fixture → refresh 가 **실패**(FRESH 아님) ②메시지에 행 라벨과 기대/실제 칸 수 포함 ③정상 시트는 그대로 통과, 처리 시간 회귀 없음 ④**빈칸과 0 구분 보존**.

### 5-B. 연간 열 직결 (Actual 미표시 해소)
- 연간 집계(`cashflow_sheet_year_totals`)는 **시트 연간 열에서만** 쓴다. 주차 문서에서 재파생 금지.
- 연 단위 연도의 시트 열 값 ↔ 집계 문서 필드 1:1. EMPTY는 EMPTY로 저장(0으로 뭉개기 금지 — 기존 `wholeWon` 사건과 동일 원칙, PR #481 참조).
- 수용 기준: p1773651024850 fixture → 2025 집계 = 317,449,417. 상태 분포에 EMPTY 보존.

### 5-C. 주차 문서 생성 게이트
- 반영 파이프라인에서 연 단위 관리 연도의 주차 문서 생성을 차단 (#482 `weekOrdinal` 거부 로직 재사용 또는 동일 규칙).
- 수용 기준: 연 단위 연도 데이터가 포함된 fixture 반영 → 주차 문서 생성 0건, 연간 집계만 갱신.

### 5-D. 낙오 정리 스크립트 (dry-run 전용)
- 대상: 연 단위 관리 연도의 `cashflow_weeks` 전 프로젝트 (확인된 61건+, 정확 목록은 스크립트가 산출).
- 워커는 **dry-run 스크립트와 백업 export 스크립트까지만** 작성. **라이브 실행 금지** — 실행은 코디네이터가 백업 확인 후 별도 진행.
- 출력: 프로젝트별 삭제 대상 목록, 삭제 후 재동기화(수동 반영) 필요 프로젝트 목록.

### 5-E. 사본 계보 문서화
- mirror·weeks·year_totals 각각 누가 언제 쓰는지, 반영 이후 읽기 전용인지 표로. (다음 단계 사본 축소의 입력)

## 3. 금지

- 자동 동기화 추가
- EMPTY→0 변환 (어디서든)
- 연 단위 연도 주차 문서 생성
- 라이브 DB 쓰기/삭제 (스크립트는 dry-run 출력까지)
- 판정 로직(BFF/JVM 경계) 변경 — 이 스트림은 시트→저장 구간만
- 시트 양식 추정 — 불명확하면 **질문으로 중단** (사용자 지시)
