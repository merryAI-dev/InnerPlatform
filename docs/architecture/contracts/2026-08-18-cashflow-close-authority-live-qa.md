## 즉시 적용 vs 재반입 후 적용

| 변경 | 적용 시점 | 이유 |
|---|---|---|
| 잠금 판정 (8월 열림) | **즉시** | head 를 매 요청마다 읽는다 |
| 연간 열 표시 (확인 불가 → 값) | **"시트 값 불러오기" 후** | 미러에 고정된 사실은 반입 때 만들어진다. 코드가 바뀌었다고 저절로 다시 계산되지 않는다 |

그래서 시나리오 순서가 중요하다. **A 그룹(잠금)은 지금 바로, B 그룹(연간)은 불러오기 뒤에.**

## A. 잠금 판정 — 즉시 확인 가능

### A-1. 열린 회차 월 수정에 팝업이 뜨지 않는다 (핵심)

**대상:** AXR 또는 JLIN
**전제:** 시트에서 2026-08 주차 셀 하나를 바꾼 상태 (예: `26-8-3` 매입부가세)

1. 프로젝트 현금흐름 시트 화면 → **시트 값 불러오기**
2. 변경 검토 → **반영**

| 확인 | 기대 |
|---|---|
| "마감 후 시트값 변경" 팝업 | **뜨지 않음** |
| 변경 사유 입력 | **요구되지 않음** |
| 반영 결과 | 정상 완료 |
| AXR 정책 화면의 경고 횟수 | **증가하지 않음** |

배포 전엔 여기서 팝업이 떴고 사유를 적어야 했다. 이게 고쳐졌으면 핵심은 통과다.

### A-2. 잠긴 달은 여전히 잠겨 있다 (회귀)

**대상:** AXR 또는 JLIN
**전제:** 시트에서 2026-07 주차 셀 하나를 바꾼 상태

1. 시트 값 불러오기 → 반영

| 확인 | 기대 |
|---|---|
| "마감 후 시트값 변경" 팝업 | **뜸** |
| 사유 없이 반영 | **거부** (`cashflow_closed_month_reason_required`) |
| 사유 입력 후 반영 | 완료, 경고 +1 기록 |

이게 안 뜨면 잠금이 풀린 것이므로 **즉시 보고.** (JVM 이 뒤에서 한 번 더 막으니 데이터가 깨지진 않지만 표시 계약 위반이다.)

### A-3. 회차 경계가 프로젝트마다 맞다

**대상:** 전남글로벌 (회차 2026-07, 지평선 2026-06)

| 셀 | 팝업 |
|---|---|
| 2026-06 | 뜸 |
| 2026-07 | **안 뜸** |

AXR·JLIN 과 한 달 어긋난 게 각자 맞게 나오면 규칙이 head 를 읽고 있는 것이다.

### A-4. 연간 연도 셀은 잠기지 않는다

**대상:** 아무 프로젝트
**전제:** 시트에서 2025 연간 열 값 하나를 바꾼 상태

| 확인 | 기대 |
|---|---|
| 팝업 | **안 뜸** |
| 반영 | 정상 |

2025 는 연간형이라 월별 CLOSED 로 해석하지 않는다 (계약). 팝업이 뜨면 연도 규칙이 깨진 것이다.

## B. 연간 열 표시 — "시트 값 불러오기" 후

**A-1 을 하면서 이미 불러오기를 했다면 여기서 바로 확인한다.**

### B-1. JLIN 2025 연간 열

| 항목 | 배포 전 | 기대 |
|---|---|---|
| 매출액(입금) | 확인 불가 | **162,404,550** |
| MYSC 선입금 - MYSC 인건비 | 확인 불가 | **미입력** |
| 직접사업비(공급가액) | 확인 불가 | **미입력** |
| 입금 합계 | 162,404,550 | 162,404,550 (**변화 없음**) |

합계 행이 바뀌면 안 된다. 합계는 시트 선언값 그대로다.

### B-2. AXR 2024·2025 연간 열

| 항목 | 배포 전 | 기대 |
|---|---|---|
| 전 항목 | 확인 불가 | **0** |
| 합계 | 0 | 0 |

시트의 그 열이 실제로 전부 0 이다.

### B-3. 2027~2032 연간 열도 같은 규칙

빈 항목은 "미입력", 값 있는 항목은 숫자. **"확인 불가"가 하나라도 남아 있으면 보고.**

### B-4. 주차 열(2026)은 그대로

2026 주차 60칸은 이 변경과 무관하다. 배포 전과 같아야 한다.

## C. 관리자 재오픈 — AXR 정책 화면

**화면:** `/axr/cashflow-period-policy`
**권한:** 요청은 프로젝트 활성 운영 사용자, 승인은 `admin` 또는 지정 승인자
**주의:** 재오픈 승인은 되돌릴 수 없고 경고가 영구 기록된다. **테스트용으로 하나만.**

### C-1. 재오픈 요청 → 승인 → 지평선이 한 달 뒤로

**대상:** 전남글로벌 (지평선 2026-06, 프로젝트가 작아 안전)

1. 정책 화면에서 전남글로벌 선택 → 상태 확인: `closedThrough=2026-06`, `회차 2026-07`
2. **재오픈 요청** (사유 입력)
3. 승인자 계정으로 **승인**

| 확인 | 기대 |
|---|---|
| head `closedThrough` | 2026-06 → **2026-05** |
| head `settlementMonth` | 2026-07 → **2026-06** |
| 경고 횟수 | **+1** |
| 재오픈 횟수 | **+1** |

### C-2. 재오픈 후 잠금 판정이 즉시 따라온다 (핵심 회귀)

C-1 직후, 같은 프로젝트에서:

| 셀 | 배포 전이라면 | 기대 |
|---|---|---|
| 2026-06 | 잠김 | **열림** — 팝업 안 뜸 |
| 2026-05 | 잠김 | 잠김 — 팝업 뜸 |

sheet-lab 이 head 를 실시간으로 읽으므로 재오픈 즉시 반영돼야 한다. **한 발 늦게 반영되면 어딘가 캐시가 있는 것이니 보고.**

### C-3. 최신 지평선만 재오픈 가능

전남글로벌에서 `2026-03` 같은 중간 달을 재오픈 요청 시도.

| 기대 |
|---|
| 거부 — `LATEST_HORIZON_ONLY` |

한 달씩만 뒤로 간다. 중간 달을 골라 열 수 없다.

### C-4. 권한 없는 계정의 승인은 거부

`pm` 또는 `viewer` 계정으로 승인 시도.

| 기대 |
|---|
| 403 · `DECISION_FORBIDDEN` |

### C-5. 재결산으로 원복

C-1 로 연 전남글로벌을 다시 결산해서 `closedThrough=2026-06` 으로 되돌린다. 재결산 흐름이 정상 동작하는지도 함께 본다.

| 확인 | 기대 |
|---|---|
| head `closedThrough` | 2026-05 → **2026-06** |
| head `revision` | +1 |
| 2026-06 셀 | 다시 잠김 |

## 프로젝트별 체크리스트

세 프로젝트는 상태가 다르므로 **셋 다** 돌린다. 각각 다른 것을 잡는다.

| | 회차 | 지평선 | 수정 이력 | 이 프로젝트만 잡는 것 |
|---|---|---|---|---|
| AXR | 08 | 07 | 0 | 8월 오잠금 해소 — 깨끗한 케이스 |
| JLIN | 08 | 07 | **1건** | 같은 증상 + `amendedCurrent=true` 경로. 연간 표시가 revision 3개 일치에 걸리는 취약 구간에 이미 들어와 있다 |
| 전남글로벌 | **07** | **06** | 0 | 경계가 한 달 다르다 → head 를 프로젝트별로 읽는지 · 재오픈 대상 |

### AXR프로젝트경비

```
[ ] 시트 값 불러오기 (미러 재생성)
[ ] B-2  2024·2025 연간 열 전 항목 → 0  ("확인 불가" 0건)
[ ] B-1  합계 행 변화 없음 (0)
[ ] A-1  26-8-x 셀 수정 → 반영 → 팝업 안 뜸, 사유 요구 없음
[ ] A-2  26-7-x 셀 수정 → 반영 → 팝업 뜸 → 사유 없이 거부 → 사유 넣고 완료
[ ] A-4  2025 연간 셀 수정 → 팝업 안 뜸
[ ]      A-2 뒤 정책 화면 경고 횟수 = 1  (A-1·A-4 는 안 올렸어야 함)
```

### JLIN IBS

```
[ ] 시트 값 불러오기
[ ] B-1  2025 매출액(입금) → 162,404,550
[ ] B-1  2025 MYSC 선입금-인건비 → 미입력
[ ] B-1  2025 입금 합계 → 162,404,550 (변화 없음)
[ ] B-3  2027~2032 "확인 불가" 0건
[ ] A-1  26-8-x 셀 수정 → 팝업 안 뜸
[ ] A-2  26-7-x 셀 수정 → 팝업 뜸
[ ] ⚠   불러오기 후 연간 열이 다시 "확인 불가"로 돌아가지 않는지 — 이 프로젝트만
         (수정 이력이 있어 revision 일치 검사를 탄다. 불러오기 → 반영 안 하고 화면 새로고침 → 연간 열 확인)
```

마지막 항목이 JLIN 고유다. 불러오기만 하고 반영을 안 하면 미러 revision 이 어긋나서 `amendedSheetFormulaSnapshot` 이 `UNAVAILABLE` 을 낼 수 있다. **그건 이번 변경 범위 밖의 기존 동작**이지만, 나타나면 어떤 조건에서 나타났는지 기록해 둔다. 반영까지 하면 다시 일치한다.

### 2026전남글로벌

```
[ ] 시트 값 불러오기
[ ] B-1  2025 연간 열 → 미입력 (이 프로젝트는 값 없음)
[ ] A-3  26-7-x 셀 수정 → 팝업 안 뜸  (AXR·JLIN 과 달리 7월이 열려 있음)
[ ] A-3  26-6-x 셀 수정 → 팝업 뜸
[ ] C-1  정책 화면 → 재오픈 요청 → 승인 → closedThrough 06→05, 경고 +1
[ ] C-2  직후 26-6-x 셀 수정 → 팝업 안 뜸 (즉시 반영)
[ ] C-2  26-5-x 셀 수정 → 팝업 뜸
[ ] C-3  2026-03 재오픈 요청 → 거부 (LATEST_HORIZON_ONLY)
[ ] C-4  pm 계정 승인 시도 → 403
[ ] C-5  재결산 → closedThrough 05→06 복귀
```

C 그룹은 **이 프로젝트에서만** 한다. 재오픈 승인은 되돌릴 수 없고 경고가 영구 기록된다.

### 순서 제안

1. AXR 전부 → 2. JLIN 전부 → 3. 전남글로벌 A·B → 4. 전남글로벌 C → 5. 스크립트 대조 (D)

C 를 맨 뒤로 두는 이유: 실패하면 원복(C-5)까지 해야 하니, 나머지가 다 통과한 걸 확인한 뒤에 손댄다.
