# 참여율 프로젝트 구성 보기 계약

- 날짜: 2026-08-24
- 결정: 보람
- 대상: 관리자 참여인력 대시보드의 포트폴리오 View

## 표시 원칙

- `전체 인력` View는 지금처럼 사람별 12개월 합계만 보여 준다. 프로젝트 상세 펼치기를 만들지 않는다.
- 사용자가 저장한 규칙 View는 사람별 행을 기본으로 접어 둔다.
- 사람별 `참여 사업` 버튼을 펼치면 같은 표와 같은 12개월 열 아래에 프로젝트별 기여율을 표시한다.
- 펼침은 표시만 바꾼다. 추가 API 조회, Firestore 읽기, Google Sheets 읽기 또는 쓰기를 만들지 않는다.

## 서버 집계 계약

- 서버는 규칙에 매칭된 전체 사업을 `사람 × 프로젝트 × 선택 연도 월`로 집계한다.
- 프로젝트 정체성은 이름이 아니라 `projectId`다. 같은 사업의 여러 stint는 하나로 합치고, 이름이 같은 다른 사업은 나누어 둔다.
- 사람 합계는 프로젝트별 월 기여율의 합과 같아야 한다.
- `projectCount`는 선택 연도에 소유한 월이 하나라도 있는 고유 프로젝트 수이며, 상세 프로젝트 수와 같다.
- `전체 인력` 응답은 사람 합계를 유지하되 프로젝트 상세 배열은 비워 둔다.

## 셀 상태

| 상태 | 표시와 합산 |
|---|---|
| 명시적 `0` | `0%`, 확인된 값으로 합산 |
| 투입기간 안 빈칸 | `미입력`, 합산값은 0이고 미입력 상태 유지 |
| 투입기간 밖 | `—`, 참여 사업 수와 합산에서 제외 |
| 숫자와 미입력 혼합 | 숫자와 `미입력 있음`을 함께 표시 |

PROJECT_TEAM_SYNC가 소유한 같은 사람·사업·월에는 MANUAL 값을 더하거나 빈칸을 보충하지 않는다.

## 정산 시스템 후보

- 규칙 관리의 정산 시스템 후보는 프로젝트 등록/수정의 정산 시스템 목록과 같은 순서·코드를 쓴다.
- 현재 사업이 0개인 정산 시스템도 `0개`로 표시하고 선택할 수 있다.
- 저장된 사업에서 관측된 legacy 정산 분류는 기본 목록 뒤에 안정적으로 표시한다.
- 규칙을 저장해도 프로젝트나 기존 규칙을 자동 수정하지 않는다.

## 접근성·호환성

- 펼침 제어는 키보드로 조작 가능한 버튼이며, 펼침 상태와 상세 영역의 관계를 접근성 속성으로 제공한다.
- View 또는 연도를 바꾸면 이전 펼침 상태를 초기화한다.
- 프로젝트 상세 필드가 없는 이전 서버 응답은 기존 사람별 합계 화면으로 안전하게 표시한다.
