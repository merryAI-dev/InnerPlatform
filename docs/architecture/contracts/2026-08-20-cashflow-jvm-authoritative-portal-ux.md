# 캐시플로우 JVM 기준과 실무자 포털 결산 UX

**Date:** 2026-08-20

**Status:** 결정됨 — 포털 UI 적용

## 결정

캐시플로우의 주간 정산과 월결산은 실무자 포털에서 한 화면에 보이되, 업무 정책과 명령은 계속 분리한다.

- 주간 정산은 실무자 완료 요청과 조직장 확정의 상태·권한·마감을 그대로 사용한다.
- 월결산은 실무자 결산 요청과 조직장 승인/재오픈의 상태·권한·마감을 그대로 사용한다.
- 두 흐름 사이에 자동 전이, 공통 상태, 공통 쓰기 명령을 만들지 않는다.
- 포털은 기존 JVM/BFF 응답을 표시만 한다. 월결산 이번 달·다음 달 progress는 JVM이 내려준 12개월 달력과 상태를 사용한다.
- 관리자 화면은 이 UX 변경의 범위에 포함하지 않는다.

## 포털 표시 규칙

포털에는 `결산`이라는 단일 진입 화면 안에 주간 정산과 월결산을 독립된 영역으로 둔다. 각 영역의 주 버튼은 기존 handler를 호출하고, 서버가 허용한 action에 따라 문구와 disabled/loading 상태만 바꾼다. 회수·재오픈처럼 되돌리기 성격이 있는 동작은 기존 확인 흐름을 유지한다.

월결산 progress는 다음 두 항목을 읽기 전용으로 표시한다.

1. 선택한 월: 현재 요청/승인 상태와 JVM 마감 시각
2. 다음 월: JVM 12개월 상태 배열의 해당 월 상태와 마감 시각

다음 월의 요청 기록이 없으면 완료나 승인 상태를 추정하지 않고 `요청 전`으로 표시한다. 데이터가 없거나 마감이 없으면 progress를 임의로 계산하지 않고 `확인 불가`로 둔다.

## 변경하지 않는 것

- JVM/BFF 계약과 마감 계산
- 주간·월결산 mutation handler, 권한 판정, idempotency
- Firestore 읽기/쓰기 경로
- 관리자 `ProjectCashflowSheetPage`

이 문서는 UI 표시를 합치는 것이 업무 정책을 합치는 것이 아님을 명확히 하기 위해 남긴다.
