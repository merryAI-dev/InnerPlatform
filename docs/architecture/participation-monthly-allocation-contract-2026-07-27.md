# 월별 인건비·참여율 관리 계약

## 목적

운영사가 관리하는 인건비 시트의 한 행을 그대로 보존한다. 한 사람의 참여율만 합산하는 화면이 아니라, **프로젝트별·인력별·월별 참여 상태와 지급액**을 함께 조회하고 위험을 판단한다.

원본 시트의 계산 결과를 바꾸거나 플랫폼이 다시 계산하지 않는다. 플랫폼은 입력값을 저장하고, 필요한 합계와 위험 신호만 별도로 만든다.

## 현재 구조와 한계

현재 `ParticipationEntry`는 아래만 가진다.

- 한 사람의 프로젝트 참여율 (`rate`)
- 시작·종료월 (`periodStart`, `periodEnd`)
- 정산 시스템과 프로젝트 정보

따라서 `3월 10% / 4월 30%`, 월별 지급액, 월별 소계, 같은 사람이 중간에 참여율을 바꾼 이력을 표현할 수 없다. 현재의 전체 기간 합산 100% 위험도 월 단위 과부하를 정확히 알려주지 못한다.

## 원본 시트에서 받는 값

| 시트 열 | 플랫폼 의미 | 보존 규칙 |
| --- | --- | --- |
| 이름(본명) | 인력 식별자 | 사내 인력 ID와 매칭하되, 원본 이름도 함께 보관 |
| 세부 담당 직무 | 프로젝트 내 역할 | 원문 그대로 저장 |
| 참여율 | 계획 참여율 | 숫자 그대로 저장 |
| 총 참여기간(개월) | 시트 표시값 | 검증용 표시값으로 보관, 월 O 개수로 덮어쓰지 않음 |
| 3~12월 서류 참여율 | 해당 월 참여율 | `null`, `0`, `0 초과 %`를 구분해 저장 |
| 월별 지급액 | 해당 월 실제/예정 지급액 | `null`, `0`, 양수, 음수를 구분해 저장 |
| 소계·총계 | 시트 계산 결과 | 원본 control total로 보관, 플랫폼이 원본을 수정하지 않음 |

월별 참여율은 boolean이 아니다. `0%`는 명시적으로 참여하지 않음을 적은 값이고, 공란은 미입력이다. `0원`도 지급액을 명시적으로 0으로 적은 것이므로 공란과 다르다.

## 제안 데이터 모델

### 1. 참여 배정 행 (`project_participation_assignment`)

한 프로젝트·한 인력·한 역할의 원본 행이다.

```
id
project_id
member_id              // 매칭 불가하면 null
source_member_name     // 원본 이름 보존
role_name
participation_rate
source_total_months    // 시트의 총 참여기간(개월)
source_total_amount    // 시트의 총계
source_snapshot_id
created_at, updated_at
```

### 2. 월별 배정 (`project_participation_assignment_month`)

원본 행의 각 월을 한 건으로 보존한다. 키는 `(assignment_id, year_month)`이다.

```
assignment_id
year_month
document_rate          // null | 0~100 (%), 월별 서류 참여율
payment_amount         // null | 0 | signed money
source_cell_reference  // 예: "인건비(운영사)!J12"
source_snapshot_id
```

`document_rate`와 `payment_amount`는 각각 독립된 값이다. 플랫폼은 둘을 boolean으로 변환하지 않는다. `payment_amount`는 금액을 임의로 보정하지 않으며, 음수는 반환·정산조정일 수 있으므로 그대로 저장하고 경고의 근거로만 쓴다.

### 3. 원본 스냅샷 (`participation_source_snapshot`)

시트 불러오기마다 원본 파일/탭/불러온 시각/행별 해시/control total을 남긴다. 최신 스냅샷이 조회 기본값이지만 과거 불러오기 결과를 덮어쓰지 않는다.

## 계산 규칙

1. **월별 참여율 위험**: 같은 인력의 같은 `year_month`의 `document_rate`를 합산한다. `null`은 합산에서 제외하고 `0`은 0으로 포함한다. 정산 시스템별 교차검증 규칙은 기존 규칙을 재사용한다.
2. **지급액 검증**: 각 월의 행 금액 합계와 시트의 월 소계를 비교한다. 다르면 오류로 보정하지 않고 `원본 시트 값 불일치`로 표시한다.
3. **기간 검증**: 참여율이 `0% 초과`인 월 수와 `총 참여기간(개월)`이 다르면 경고한다. 원본값을 자동 수정하지 않는다.
4. **총계 검증**: 월별 지급액 합계와 행 총계가 다르면 경고한다. 시트의 총계가 기준값이다.
5. **참여율과 지급액 분리**: 참여율 0%·금액 있음, 참여율 있음·금액 0원 모두 저장 가능하다. 해석이 필요한 경우만 확인 항목으로 만든다.

## 화면 원칙

### 프로젝트 인건비 매트릭스

시트와 같은 행 순서와 월 열을 유지한다.

- 좌측 고정: 이름, 역할, 참여율, 총 참여기간, 총계
- 월 열: 서류 참여율(`미입력 / 0% / n%`)과 지급액을 같은 셀 안에서 분리 표시
- 하단: 원본 시트의 월 소계·총계를 표시하고, 플랫폼 계산값과 다를 때만 경고
- 조회 기본값은 최신 원본 스냅샷이다.

### 월별 입력 레퍼런스 반영

참고 화면처럼 한 사람의 행을 가로로 두고, `1월~12월`을 반복 열로 둔다. 각 월에는 **입력값**과 그 아래의 **계산/검증 결과**를 분리해 보여준다.

- 월별 서류 참여율은 입력값이다. 예: `3월 10%`, `4월 30%`.
- 월별 지급액과 합계는 참여율과 다른 값으로 취급한다.
- 월별 결과가 계산되더라도 원본에서 받은 참여율·금액을 덮어쓰지 않는다.
- 전체 행 끝에는 원본 총계와 플랫폼 검증 결과를 나란히 둔다.

이미지의 월별 `D/R`는 **서류 참여율 한 칸**으로 단순화한다. 실제 참여율은 받지 않으며, 원본 시트의 서류 값만 저장·조회·위험 계산에 사용한다.

### 인력별 참여율 위험 화면

기존의 전체 기간 합산 대신 월을 선택하거나, 위험한 월만 모아 본다.

- `2026-07 · 변민욱(보람) · 110%`
- 상세에서 해당 월의 프로젝트·역할·참여율·지급액을 함께 본다.

## 시스템 경계

- **프론트**: 시트 모양의 조회, 필터, 경고 표시. 금액·참여율 계산의 최종 권위가 아니다.
- **BFF**: 최신 스냅샷과 월별 조회 모델 조합.
- **JVM**: 원본 스냅샷, 배정 행, 월별 배정, 검증 결과를 한 트랜잭션으로 저장.
- **시트 연동**: 명시적 불러오기만 허용한다. 자동 동기화·시트 역쓰기 없음.
- **Cashflow 연동**: 이번 범위에서는 자동 전표 생성 금지. 인건비 지급액을 `MYSC 인건비`와 연결하려면 프로젝트·월·원장행 연결키를 별도 계약으로 확정한 뒤 진행한다.

## 단계별 구현

1. 스냅샷/배정행/월별배정 JVM 계약과 마이그레이션
2. 고정 시트 형식 parser: 월별 서류 참여율 null/0/%와 금액 null/0/음수 보존
3. BFF 월별 매트릭스·검증 응답
4. 프로젝트 인건비 매트릭스 화면
5. 인력별 월 참여율 위험 화면으로 기존 참여율 관리 교체
6. 실제 시트 1개로 행·월·금액·총계 검증 QA

## 구현 전 확정할 질문

1. 월별 금액은 **실제 지급액**인가요, 아니면 **예정 지급액**인가요? 혼재하면 상태 열이 하나 더 필요합니다.
2. 이미지의 `O/X` 표시는 원본 시트의 지급/확인 표시인가요? 기본안은 이 표시를 참여율 계산에 쓰지 않고, 월별 참여율 수치와 분리 보관하는 것입니다.
3. 한 사람이 같은 프로젝트에서 역할을 두 개 맡으면 시트에서도 두 행으로 유지하나요? 기본안은 두 행을 보존합니다.
4. 인력 기준 원본은 운영사 인건비 시트 하나인가요, 아니면 e나라도움·KOICA별 시트를 함께 받나요? 기본안은 여러 원본을 스냅샷으로 분리해도 같은 월 화면에서 합산합니다.
