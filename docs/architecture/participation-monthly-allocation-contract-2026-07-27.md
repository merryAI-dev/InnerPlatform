# 월별 인건비·참여율 관리 계약

## 목적

운영사가 관리하는 인건비 시트의 한 행을 그대로 보존한다. 한 사람의 참여율만 합산하는 화면이 아니라, **프로젝트별·인력별·월별 서류 참여율**을 조회하고 위험을 판단한다.

원본 시트의 계산 결과를 바꾸거나 플랫폼이 다시 계산하지 않는다. 플랫폼은 입력값을 저장하고, 필요한 합계와 위험 신호만 별도로 만든다.

## 현재 구조와 한계

현재 `ParticipationEntry`는 아래만 가진다.

- 한 사람의 프로젝트 참여율 (`rate`)
- 시작·종료월 (`periodStart`, `periodEnd`)
- 정산 시스템과 프로젝트 정보

따라서 `3월 10% / 4월 30%`처럼 같은 사람이 중간에 참여율을 바꾼 이력을 표현할 수 없다. 현재의 전체 기간 합산 100% 위험도 월 단위 과부하를 정확히 알려주지 못한다.

## 원본 시트에서 받는 값

| 시트 열 | 플랫폼 의미 | 보존 규칙 |
| --- | --- | --- |
| 이름(본명) | 인력 식별자 | 사내 인력 ID와 매칭하되, 원본 이름도 함께 보관 |
| 세부 담당 직무 | 프로젝트 내 역할 | 원문 그대로 저장 |
| 참여율 | 계획 참여율 | 숫자 그대로 저장 |
| 총 참여기간(개월) | 시트 표시값 | 검증용 표시값으로 보관, 월 O 개수로 덮어쓰지 않음 |
| 3~12월 서류 참여율 | 해당 월 참여율 | `null`, `0`, `0 초과 %`를 구분해 저장 |
| 소계·총계 | 시트 계산 결과 | 원본 control total로 보관, 플랫폼이 원본을 수정하지 않음 |

월별 참여율은 boolean이 아니다. `0%`는 명시적으로 참여하지 않음을 적은 값이고, 공란은 미입력이다.

## 제안 데이터 모델

현재 단계에서는 기존 Firestore 문서 `orgs/{tenantId}/partEntries/{entryId}`를 실제 저장소로 사용한다.

```
ParticipationEntry.monthlyRates = {
  "2026-03": 10,   // 명시적 10%
  "2026-04": 0,    // 명시적 0%
  "2026-05": null  // 시트 공란(미입력)
}
```

프로젝트·인력·역할 등 기존 `ParticipationEntry`의 식별값은 그대로 쓰고, `monthlyRates`만 월별 서류 참여율을 보존한다. 별도 JVM 테이블·BFF 조회 경로는 만들지 않는다.

## 계산 규칙

1. **월별 참여율 위험**: 같은 인력의 같은 `year_month`의 `document_rate`를 합산한다. `null`은 합산에서 제외하고 `0`은 0으로 포함한다. 정산 시스템별 교차검증 규칙은 기존 규칙을 재사용한다.
2. **기간 검증**: 참여율이 `0% 초과`인 월 수와 `총 참여기간(개월)`이 다르면 경고한다. 원본값을 자동 수정하지 않는다.

## 화면 원칙

### 프로젝트 인건비 매트릭스

시트와 같은 행 순서와 월 열을 유지한다.

- 좌측 고정: 이름, 역할, 프로젝트
- 월 열: 서류 참여율(`미입력 / 0% / n%`)만 표시
- 조회 기본값은 Firestore의 최신 참여율 문서다.

### 월별 입력 레퍼런스 반영

참고 화면처럼 한 사람의 행을 가로로 두고, `1월~12월`을 반복 열로 둔다.

- 월별 서류 참여율은 입력값이다. 예: `3월 10%`, `4월 30%`.
- 월별 결과가 계산되더라도 원본에서 받은 참여율을 덮어쓰지 않는다.

이미지의 월별 `D/R`는 **서류 참여율 한 칸**으로 단순화한다. 실제 참여율은 받지 않으며, 원본 시트의 서류 값만 저장·조회·위험 계산에 사용한다.

### 인력별 참여율 위험 화면

기존의 전체 기간 합산 대신 월을 선택하거나, 위험한 월만 모아 본다.

- `2026-07 · 변민욱(보람) · 110%`
- 상세에서 해당 월의 프로젝트·역할·참여율을 함께 본다.

## 시스템 경계

- **프론트**: 시트 모양의 조회, 필터, 경고 표시. 수정 기능은 제공하지 않는다.
- **실제 DB**: Firestore `partEntries`가 현재 기능의 운영 저장소다. 로컬 seed는 개발용일 뿐 운영 조회에 쓰지 않는다.
- **BFF/JVM**: 이번 조회 전용 범위에는 새 경로를 만들지 않는다. 결산·현금흐름처럼 서버 트랜잭션이 필요한 계약이 확정될 때만 별도 경로를 검토한다.
- **시트 연동**: 원본 반영 방식은 추후 별도 계약으로 정한다. 자동 동기화·시트 역쓰기는 하지 않는다.

### 권한

- 관리자는 월별 서류 참여율을 **조회만** 할 수 있다.
- 관리자 화면에는 행 추가·수정·삭제·시트 반영 버튼을 두지 않는다.
- 원본 반영 경로가 확정되기 전까지 관리자 화면에서 DB 값을 직접 고치지 않는다.

## 단계별 구현

1. `ParticipationEntry.monthlyRates`의 `null / 0 / %` 계약과 관리자 조회 화면
2. 실제 시트 1개를 Firestore `partEntries`에 반영하는 입력 경로 확정
3. 인력별 월 참여율 위험 화면으로 기존 참여율 관리 교체
4. 실제 시트 1개로 월별 참여율 QA

## 구현 전 확정할 질문

1. 한 사람이 같은 프로젝트에서 역할을 두 개 맡으면 시트에서도 두 행으로 유지하나요? 기본안은 두 행을 보존합니다.
2. 인력 기준 원본은 운영사 인건비 시트 하나인가요, 아니면 e나라도움·KOICA별 시트를 함께 받나요? 기본안은 여러 원본을 기존 참여율 문서에 반영합니다.
